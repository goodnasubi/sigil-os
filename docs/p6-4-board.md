# P6-4 組み込み実機の構成（ADR 0054 決定 7）

P6-4 の対象は x86-64 の組み込み実機 1 構成である。本書は、その構成を **要件として固定**し、
実機の機種の選定を **提案**としてまとめる。**機種はまだ決まっていない**（下の「機種の選定」）。
実機の購入・発注は、人間の負担と費用に直結するため、所有者の判断に委ねる（この PR では行わない）。

## 固定する構成（要件）

実機の機種を問わず、次を満たす 1 構成を P6-4 の対象とする。これは P6-1 の起動契約
（[boot-contract.md](boot-contract.md)）と、P6-4 で観測する機器 1 種から導いた。

| 項目 | 固定する値 | 理由 |
|---|---|---|
| CPU | x86-64（64 ビットのロングモード） | ADR 0054 決定 7 |
| ファームウェア | UEFI（64 ビット）。Secure Boot は無効にできること | 起動契約。試験用のローダーは未署名 |
| 起動媒体 | USB 接続のストレージ（USB メモリ）。`make usb` が作る `build/sigil-os-usb.img` を書き込む | 組み込み実機で入手・書き換えが容易。QEMU でも同じ経路を近似できる（`make check-p6-4`） |
| 起動順序 | UEFI のブートメニューで USB を最優先にする。フォールバックの `\EFI\BOOT\BOOTX64.EFI` を使うため、ブートエントリの登録は要らない | 起動契約 |
| メモリ | 256 MiB 以上 | 試験用カーネル窓 `[0x02000000, 0x02200000)` と UEFI のメモリマップを収めるため |
| 観測する機器 1 種 | **COM1 の 16550 互換 UART**（I/O ポート `0x3f8`、115200 baud、8N1） | 起動契約がシリアル出力を COM1 に固定している。専用のドライバーなしで、機器への入出力を観測できる |
| 観測の取得 | 実機の COM1（RS-232 の D-Sub 9 ピンまたはヘッダー）を、USB-シリアル変換などでホストに接続して記録する | 実機には画面を使わない |
| 不要なもの | PCI の VMware 機器（PVSCSI・VMXNET3）。ESXi。ネットワーク | P6-4 は実機そのものを検証環境にする |

実機の COM1 が I/O ポート `0x3f8` の 16550 互換でない場合（メモリマップドの UART だけを持つ機種など）は、
その機種は本構成に **合わない**。機種の選定ではこの点を最初に確かめる。

## 機種の選定（提案。決定ではない）

次の順で絞り込むことを提案する。機種名は、この環境からベンダーの公式資料を確認できていないため、
ここでは挙げない。所有者が購入を決める前に、各条件を公式資料と実機で確かめる必要がある。

1. **必須（上の表を満たす）**: x86-64、UEFI（Secure Boot を無効にできる）、USB から起動できる、COM1 が
   I/O ポート `0x3f8` の 16550 互換（レガシー COM ポートを持つ、または BIOS 設定で COM1 に割り当てられる）。
2. **強く望ましい**: シリアルがボード上の D-Sub 9 ピンまたはヘッダーに出ている（USB-シリアル変換を挟める）。
   メモリ 256 MiB 以上は事実上どの機種でも満たす。
3. **望ましい**: 産業用・組み込み用として長期供給される。BIOS 設定でシリアルのリダイレクトを無効にできる
   （ファームウェアがシリアルを占有すると、起動ログと混ざる）。

提案する進め方:

- 所有者が、上の必須条件を満たす候補を 1〜2 機種に絞る（予算・入手性による）。
- 候補ごとに、公式資料で「UEFI」「Secure Boot の無効化」「COM1 の I/O ポート」を確かめる。
- 決まった機種を、本書の「固定する構成」の下に「機種」として追記する（別 PR）。
- 実機が届いたら、[p6-4-verification.md](p6-4-verification.md) の「実機での手順」を実施して記録する。
